# 抽取前的原文编号

`crawler.parse.indexing.index_documents` 是 #43 的纯函数入口，不请求网站、不调用模型。它把快照的正文和附件编成句子、日期、链接和邮箱的索引，供 #18 的实验及 #44 的抽取使用。时间值和最终证据的格式以[总体设计 §8.2](design.md#82-抽取)为准。

## 输入和调用

每个 `Document` 对应快照中的一份文字：

| 字段 | 含义 |
| --- | --- |
| `text` | 快照正文或附件的原始文字，不另做清洗 |
| `attachment` | 正文不填；附件使用快照中的序号，从 0 开始，不因附件文字为空而重新编号 |
| `url` | 这份文档的地址，供相对链接解析使用；正文未填时使用 `source_url` |
| `hyperlinks` | 上游已定位的超链接，包含文字的起止下标和原始 `href`；纯文本网址和邮箱无需传入 |

```python
from crawler.parse.indexing import Document, index_documents

# page 是现有的 NoticePage，context 是 ExtractionContext。
documents = [Document(page.text)]
documents.extend(
    Document(attachment.info.text, attachment=position, url=attachment.info.url)
    for position, attachment in enumerate(page.attachments)
)
index = index_documents(
    documents,
    published_on=context.published_on,
)
```

`source_url` 是可选的通知来源地址，不是来源列表页。现有 `Steps.extract(page, context)` 不接收通知网址，所以纯文本编号不要求调用方提供它，也不会从来源列表地址猜出通知网址。通知与快照的关联仍由现有一轮流程在提交结果时保留。若调用方确实掌握通知网址，可传入 `source_url=notice_url`。

相对超链接必须有真实的文档地址：优先用 `Document.url`，其次用 `source_url`；两者都没有时抛 `ValueError`。遇到跳转时，上游可以把实际页面地址放在正文的 `Document.url` 中。快照编号由调用方保留；这份索引只属于本次输入，不是跨通知、跨快照的全局编号。

## 编号和原文位置

| 集合 | 编号示例 | 内容 |
| --- | --- | --- |
| `index.sentences` | `S1` | 句子的来源、起止位置和原文 |
| `index.dates` | `D1` | 所属句子，以及日期原文、位置、时间值和解析问题 |
| `index.links` | `L1` | 所属句子、原文位置、显示文字、实际网址及原始 `href` |
| `index.emails` | `E1` | 所属句子、原文位置、显示文字、邮箱地址及原始 `href` |

正文在前，附件按原序号在后；每类编号从 1 开始，按出现顺序分配。相同输入重复调用产生相同编号，重复内容按位置分别保留，不按值去重。

所有 `start`、`end` 都是**所属文档的 Python 字符串下标**，左闭右开，不是字节下标，也不是浏览器的 UTF-16 下标。句子的 `attachment` 确定文档；日期、链接和邮箱通过 `sentence_id` 找到文档。每个记录的原文都等于 `document.text[start:end]`。

切句使用句号、问号、感叹号、分号和换行；英文句点在后接空白或文末时切句，但片段开头的 `1.`、`3.1.` 等列表编号与后续内容保留在一起。逗号、冒号、小数点和文件名内部的点不切。片段两端空白只从选择范围排除，不改写快照。网址、邮箱和已定位的超链接内部不切，即使超链接文字跨行。

不会按字数截断句子。`index.evidence(sentence_id)` 返回现有的 `Evidence` 类型，附件证据带 `attachment`。未知句子编号抛 `KeyError`；超过接口证据长度上限的句子会被该类型拒绝，调用方须明确处理，不能静默截短或绕过上限。

## 日期

`DateMention.match` 包含 `text`、`start`、`end`、`value`、`end_value` 和 `issue`。单个日期只有 `value`；时间段的 `value`、`end_value` 分别是起止时间值。

- 支持中文年月日、日期加时分、24 时或 24 点、日前、前后或左右、旬、月初或月底、只有月份、即日起，以及用「至」「到」或横线连接的日期段。
- 保留原文精度，直接使用 `contract.py` 中的时间值类型；不生成提醒用的时间戳。所有日期和时分都按北京时间理解，不读取本机时区或当前时间。
- 缺少年份、发布日期为空和跨年推断按[总体设计 §8.2](design.md#82-抽取)处理；明确写出的年份不改写。推断后再检查日期是否合法，不为闰日额外寻找其他年份。
- 时间段右端从左端继承省略的年月，跨年仍使用总体设计的半年规则。只有日号的右端不猜测为下个月，反向时间段标记为无效。
- `24:00` 保留原日期；仅在比较时间段顺序时理解为次日零点。
- 「17:00 前」「17 点前」使用到分钟的时间值，原文中的「前」保留在 `text` 和句子中；不把它误作「某日前」而提前一天。到分钟的时间值没有 `mark` 字段。带时分的「前后」「左右」尚不能用现有类型准确表达，保留原文并标记为无效。
- 缺少必要的发布日期时，保留原文，`issue="missing_publication"`；非法日期、时分或反向时间段使用 `issue="invalid_date"`。两种情况都不给可采用的时间值，不返回部分成功的时间段。
- 识别不出日期的片段仍作为句子保留。没有日期编号不等于没有日期信息，调用方不能把未识别的表达式当作确定的时间值。

日期不会从网址或邮箱内部提取；超链接的显示文字如果包含日期，仍可作为日期候选。

## 链接和上游交接

正文中直接写出的 HTTP(S) 网址和常规邮箱由程序识别，保护网址查询参数和邮箱内部的标点，排除句末标点。自动识别面向常见 ASCII 地址；不猜测裸域名的协议，也不把扫描图像中的内容当作已读取文字。

「报名平台」等显示文字本身不包含网址。上游须通过 `Hyperlink(start, end, href)` 提供它在**同一份快照文字**中的准确范围。不同位置出现相同的显示文字也须分别传入，不用全文搜索猜对应关系。`href` 可为绝对地址、相对地址或单个邮箱的 `mailto:` 地址，返回值保留原始 `href`，并解析实际目标。传入无效范围、重叠超链接、不支持的协议或重复文档来源时抛 `ValueError`。

支持的链接类型中，无法形成有效目标的内容（例如 `mailto:` 地址被网站误加句号）保留原始 `href`、文字和位置，使用 `target=None`、`issue="invalid_target"`，不猜改地址，不让该坏目标遮住同一位置可识别的纯文本邮箱。下游须检查目标非空才能采用；可识别的显示邮箱与坏超链接分别编号。

超链接映射属于 #40 的交接点。当前 `NoticePage` 没有独立的映射字段，本模块提供输入类型，不擅自修改 `NoticePage`、生成接口或实现 HTML 与文字的映射。表格关系和 OCR 质量取决于上游，本模块保留已有文字及换行，不重建丢失的结构。

原文只改变超链接目标、文字不变时，现有快照去重可能不会生成新快照。这需要另行讨论快照规则；本模块不修改去重行为。

## 下游使用和示例

模型从编号中选择，#44 按编号取值并用 `index.evidence` 组装最终字段；内部编号不替代现有接口中的 `quote` 和 `attachment`。下游还需检查编号存在、信息项与证据有关联、模型输出结构合法，以及是否确实表示报名截止或报名入口。可溯源不代表语义选择一定正确。

在 `crawler/` 中运行完整的合成示例：

```sh
uv run python -m crawler.parse.example
```

示例输出正文及附件的索引，再以固定的 `D1`、`L1` 选择组装报名时间和入口。日期、域名、文本、置信度和模型选择全部是合成的，不连外网、不调用模型。

`parse/handoff_test.py` 使用现有的 `NoticePage`、`ExtractionContext`、`Steps`、`crawl_source` 和 `Website` 验证交接：空附件不改变后续附件序号，固定选择组装的延期结果只提交截止时间，证据能在提交的快照文字中原样找到，结果由当前客户端按现有 `Extraction` 类型提交到模拟 HTTP 接口。该测试不修改共享流程，也不代表真实网站、模型或数据库归并已完成联调。
