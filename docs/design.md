# 鼠钟 · 总体设计

> 状态：草案，待评审。表结构见[数据表](data-model.md)，接口见[接口](api.md)。想法的来源和讨论见鼠洞的[征集意见帖](https://bbs.mousebaoyan.cn/t/6771)。

## 1. 目标

- **不漏截止时间**：自动收集各高校学院官网的保研通知（冬令营、夏令营、预推免、九推），整理出截止时间和要点，快到了提醒。
- **盯着发布**：关注的学院一发新通知就提醒，不用等通知出来再去找。
- **信息可信**：每一项都附原文里的那句话；原文删了也有快照；大家一起纠错，每次修改都有记录，能撤销。
- **快**：页面 1 秒内打开，在手机 QQ 里也流畅；筛选、排序、搜索即时出结果；每天抓几百个来源，也不拖慢网站。
- **好接入**：群 bot 每天发一条汇总；用户自己的 Agent 能直接查询、订阅。

暂不做：公众号的通知（第 17 节「以后」）；入营、优营名单和考核结果只作为关注学院的提醒，不整理成表。

## 2. 已定决策

| 事项 | 决定 |
| --- | --- |
| 名称 | 鼠钟，暂定，帖子里在征名；出自童谣 *Hickory Dickory Dock* 的 "The mouse ran up the clock" |
| 仓库 | `mousebaoyan/mouseclock`，MIT 许可证；`main` 只能通过 PR 合入 |
| 收录范围 | 先收计算机相关的学院和研究所，第一批先收对四非友好的（如电科、厦大、沈自）；之后按「求收录」的同求人数加 |
| 数据来源 | 以学院和研究生院的官网为准；公众号以后再试，只收官方号 |
| 往年数据 | 也收，可以按年份筛选 |
| 判别 | 先调用 System One 判别接口（比如 Jev 官方的接口）初筛，通过的再交给 LLM 抽取；用哪家和门槛用真实通知做实验后定 |
| 账号 | 不单独注册，用鼠洞账号登录；等级、角色、禁言和冻结都以鼠洞为准 |
| 访客 | 只能看几条预览，登录后看全部 |
| 提醒 | 邮件发到 `QQ号@qq.com`：订阅的项目截止前 3 天提醒，关注的学院有新通知就提醒；群 bot 每天发一条汇总 |
| 纠错 | L3 以上直接修改、审核申请，L3 以下提修改申请；每次修改都有记录，能撤销 |
| Agent | 提供 MCP 服务和 API，用个人令牌登录；Agent 不能直接修改数据，也不能审核 |
| 部署 | 网站和抓取分开：网站放在香港的服务器上，和鼠洞同一台；抓取、初筛和抽取放在上海的机器上，访问学院官网更快，也不占网站服务器的资源。两边只通过接口交接（第 16 节） |
| 技术栈 | 网站和鼠洞同一套（TypeScript、React Router、Hono、Kysely），抓取节点用 Python，数据库用服务器上的 PostgreSQL 18（第 5 节） |

## 4. 架构

```text
抓取节点（上海）
  │  领活 → 抓列表页、正文和附件 ──▶ 学院、研究生院官网（通用 / 配置 / 浏览器 / 专用适配器）
  │  整理成快照 → 初筛：判别模型看标题 → 抽取：LLM 按字段输出，每项附原文证据
  ▼  HTTPS：抓取节点主动连接，用抓取节点令牌
网站（香港，和鼠洞同一台服务器）── 数据库：1Panel 的 PostgreSQL
  ├─ 收结果：存通知和快照，归并成项目和版本，拿不准的进审核页
  ├─ 网页 / API / MCP ◀── 浏览器、用户的 Agent
  ├─ 登录 ──▶ 鼠洞（授权方）
  ├─ 邮件 ──▶ 订阅和关注的提醒
  └─ 群汇总 ◀── AstrBot 插件每天来取
```

- **两个部署单元**：抓取节点负责抓取、初筛和抽取，网站负责其余的一切。两边只通过[抓取节点接口](api.md#6-抓取节点)交接，不共享数据库，可以用不同的语言，各自部署、各自升级。
- **抓取节点不存业务数据**：要抓什么、哪些通知已经见过，都问网站；抓完把结果交给网站。网站连不上时这一轮就等着，下一轮再来。
- **只有抓取节点主动连接**：网站不连抓取节点，抓取节点放在内网也行，只要能访问外网。
- **一套业务逻辑**：网页、API 和 MCP 调用同一组服务函数，权限、订阅上限和修改记录只有一套。
- **不直接连 QQ**：群汇总由 AstrBot 插件定时来取，和鼠洞的做法一样；鼠钟不反向连接插件。

## 5. 技术选型

评判标准：
- 模型写这门技术写得准不准；
- 类型检查快不快、严不严；
- 版本稳不稳；
- 实测性能；
- 优先选主流的；服务器上已有的（1Panel 的 PostgreSQL、Redis）能复用就不加新服务。

### 5.1 选定的方案

| 部分 | 选定 | 理由 |
| --- | --- | --- |
| 网站 | 和鼠洞同一套：TypeScript 7、Node 26、React Router 8、Hono 和 `@hono/zod-openapi`、Kysely、Tailwind CSS 和 shadcn/ui；pnpm、oxlint、Prettier、Vitest、Playwright | 登录、邮件、界面风格和写法都能照搬。选型依据和框架的实测见[鼠洞的总体设计 §5.2](https://github.com/mousebaoyan/mousehole/blob/main/docs/design.md#52-选型依据) |
| 数据库 | 服务器上 1Panel 的 PostgreSQL 18 | 和鼠洞共用实例，不加新服务 |
| 抓取节点 | Python 3.14，uv 管依赖；Ruff 做 lint 和格式化，Pyright 的严格模式做类型检查，pytest 做测试 | 浏览器抓取、正文提取、PDF 和 Office 解析、中文的文字识别，Python 的库最全，代价是多一套工具链。3.15 刚发布，文字识别要用的 onnxruntime 还没有它的安装包。Pyright 和 VS Code 的 Pylance 是同一个引擎，编辑器里看到的错误和 CI 一致 |
| 抓取 | httpx（异步）请求网页，Playwright 驱动浏览器（Chromium 的无头精简版），lxml 按 CSS 或 XPath 取出列表 | 各自领域的主流库 |
| 正文、附件和文字识别 | 候选：trafilatura 取正文，pypdf 或 pdfplumber 读 PDF，python-docx 和 openpyxl 读 Office，RapidOCR 识别文字 | 都关在 `parse` 模块里，换了不影响别处；在[抓取节点原型](https://github.com/mousebaoyan/mouseclock/issues/6)里用真实的附件比较后定。不用 AGPL 许可的 PyMuPDF |
| 接口的类型 | 网站用 Zod 写接口的定义，生成 OpenAPI 文档；抓取节点从这份文档生成 Pydantic 模型 | 两边语言不同，接口的类型也只有一个来源。抓取节点用 Pydantic 校验网站的返回和模型的输出 |
| 判别接口和 LLM | 实验后定（第 8.5 节） | |

### 5.2 实测

测试机：AMD Ryzen 7 8845HS，Chromium 156（Playwright 1.64），Python 3.14。

**总表一次发给浏览器**（第 14 节）：造一年的项目（200 所学校、600 个学院），只带总表要用的字段；在 Chromium 里解析，按全部筛选条件和关键词筛一遍，再按截止时间排序。手机用 CPU 降速模拟。

| 项目数 | JSON | gzip | Brotli（质量 5 / 11） | 降速 6 倍：解析 + 筛选排序 |
| --- | --- | --- | --- | --- |
| 1000 | 401KB | 62KB | 54KB / 42KB | 3.7ms + 1.3ms |
| 3000 | 1045KB | 165KB | 138KB / 105KB | 8.5ms + 3.8ms |
| 6000 | 2009KB | 321KB | 265KB / 200KB | 14.9ms + 9.3ms |

CPU 不是问题，要省的是带宽，做法见第 14 节。

**浏览器抓取**：用 Chromium 的无头精简版，不加载图片、字体和音视频。

| 测了什么 | 结果 |
| --- | --- |
| 内存（浏览器加 Playwright 的驱动） | 空载约 210–240MB；开一个页面峰值 370–450MB，看页面大小；同时开两个列表页约 410MB。完整版 Chromium 的无头模式空载就要 330MB，峰值 520MB |
| 厦大信息学院的列表页 | 浏览器 0.7 秒；普通请求 0.22 秒、39KB，标题都在 HTML 里，用不着浏览器 |
| 电科计算机学院 | 用了瑞数的反爬：先返回 202 和一段脚本，脚本设好 Cookie 后重新请求。Playwright 默认带着自动化标记（`navigator.webdriver` 为真），无头模式的 UA 里写着 `HeadlessChrome`，有一处就返回 400；关掉自动化标记、UA 里写成 `Chrome` 就能通过，UA 末尾照样写明鼠钟。首页 3.1 秒，内存峰值约 425MB；同一个会话里再开列表页，不用再过挑战 |

**文字识别**：RapidOCR（PP-OCRv6）识别一张 20 行的中文页面约 1 秒，进程峰值约 690MB；抓取节点只有 4 核，会慢几倍。

抓取节点同时开 2 个浏览器页面、一次识别一张图，峰值约 1.4GB，3.6GB 内存够用（第 16 节）。

## 6. 账号与权限

### 6.1 登录

- 用鼠洞账号登录，鼠洞做授权方，按 OAuth 2.0 授权码流程，步骤见[接口 §2](api.md#2-鼠洞登录)。两边都是自己的网站，不弹授权确认。
- **自动登录**：没有鼠钟会话的人打开页面时，鼠钟把浏览器带到鼠洞。已经登录鼠洞的，鼠洞直接带着一次性凭证跳回来，不用点；没登录鼠洞的回来按访客显示，点「登录」再走鼠洞的登录。
- **不共用 Cookie**：鼠洞的会话只发给 `bbs.mousebaoyan.cn`，鼠钟用自己的会话。这样鼠钟出了问题，也拿不到鼠洞的会话。
- **拿到的资料**：鼠洞的用户 ID、名字、头像、等级、角色、禁言和冻结状态，以及 QQ 号（只用来发邮件，不显示）。每次登录时更新，登录期间每小时从鼠洞刷新一次，所以在鼠洞被禁言、冻结或者降级，最多一小时后在这里生效。
- 鼠洞那边要加授权接口，在 mousehole 仓库里设计和实现。

### 6.2 权限

| 谁 | 能做什么 |
| --- | --- |
| 访客 | 看总表的前 5 条预览 |
| 成员 | 看全部；订阅、关注、记报名、贴学院标签、反馈、提修改申请、求收录、生成个人令牌 |
| L3 及以上 | 以上都能，还能直接修改、审核修改申请、标记已核对 |
| 管理员 | 以上都能，还能复核争议、删除项目、撤销某人的全部修改、收回某人的修改权限，管来源、院校清单和学院标签的预设 |
| 站长 | 系统设置：发信邮箱、抓取节点令牌 |

- 成员就是鼠洞的成员，也就是在群里的人。冻结的按访客算；禁言的能看、能订阅关注、能记报名，其余都不能做。
- 鼠洞的管理员和站长，在这里也是管理员和站长。
- 管理员可以单独收回某人在鼠钟的修改权限，不影响他在鼠洞的权限。

## 7. 抓取

### 7.1 来源

- 一个来源是一个通知列表页，比如学院官网的「通知公告」、研究生院的「招生信息」。一个学院可以有几个来源。
- 来源由管理员接入。群友在「求收录」里给的链接只当线索（第 10.1 节）。
- 接入时往回翻页，补上前两年的通知，作为往年数据。

### 7.2 怎么抓

| 方式 | 用在哪 | 接入要做什么 |
| --- | --- | --- |
| 通用抓取 | 列表页规整的，希望是大多数 | 只填通知列表页的地址 |
| 配置 | 结构特殊的 | 几行配置，指明列表、标题、日期和翻页在哪 |
| 浏览器抓取 | 要执行 JS 才能看到内容的 | 用浏览器打开再抓 |
| 专用适配器 | 前三种都不行的极少数网站 | 单独写代码 |

- **按建站系统做模板**：不少高校官网用的是同几家建站系统，一个模板能管一批。
- **LLM 只在接入时用**：管理员在网站上填好列表页的地址，点「试抓」；抓取节点下一次领活时领到它，抓下来，让 LLM 认出列表、标题、日期和翻页在哪，把抓到的条目和生成的配置交回网站。管理员看过没问题再保存；之后每天按配置抓，不再问 LLM。
- **不硬闯**：要登录才能看的、有验证码的不抓，标成「暂时抓不了」并写明原因。只要求用浏览器打开的脚本挑战（比如瑞数的反爬）不算：页面是公开的，人用浏览器打开就能看，浏览器抓取按[开发约定 §2](development.md#2-抓取和判别)的设置通过，UA 照样写明鼠钟。
- **已经遇到的**：电科计算机学院的官网用了瑞数的反爬，要用浏览器抓取（第 5.2 节）；浙大计算机学院的 HTTPS 连不上，只能用 HTTP，要写进配置。

### 7.3 频率和礼貌

- 平时每个来源每天抓 2 次；3–9 月和 12–1 月是旺季，每 4 小时一次。
- 同一个网站同一时间只发一个请求，两次请求之间隔 5 秒，robots.txt 的 Crawl-delay 更长时按它；遵守 robots.txt；请求头写明是鼠钟，附上联系方式。
- 失败了等下一轮再抓，一轮里不反复重试。

### 7.4 发现变化

- **新通知**：列表里出现没见过的链接，直接比网址。
- **正文变化**：还没截止的项目，每天重抓一次它的通知；正文的文字和上一份快照不同，就存一份新快照，再交给抽取。
- **删除**：通知打不开或者从列表里消失，标成「原文已删除」，快照照样能看。
- **附件**：PDF、Word、Excel 和图片都下载下来，解析出文字，图片做文字识别；附件和正文一起存进快照。

### 7.5 抓取看板

- 记下每个来源每一轮的结果：成功还是失败、失败原因（超时、403、找不到列表）、列表里有几条、新通知几条、其中有用的几条，以及 LLM 用了多少 token。
- 连续 2 轮失败的标红；旺季里 30 天没有新内容的标黄，往往是网站改版了，配置抓不到东西。
- 登录后都能看。

## 8. 判别与抽取

### 8.1 初筛

- 新通知先由判别模型看标题，必要时带上列表页的栏目名，判断是不是保研招生相关的通知：冬令营、夏令营、预推免、九推的报名通知，它们的补充、延期通知，以及入营、优营名单和考核结果。
- 调用 System One 判别接口，比如 Jev 官方的接口：对带类型的问题（是否、单选、打分）一次给出校准过的概率，快而便宜。[OneJev](https://github.com/OmniJev/OneJev) 兼容同一种接口，需要时也能自己部署；换哪家只改配置。
- 门槛宁低勿高：漏掉一条通知的代价，比多调一次 LLM 大得多。
- 判别接口不可用时，这一轮的初筛等着，不跳过初筛直接送给 LLM。
- 鼠洞的 bot 插件试过用 OneJev 筛群聊：有内容的和闲聊的分数混在一起，定不出门槛。通知标题短而规整，预计会好很多，但要用实验证明（第 8.5 节）。

### 8.2 抽取

程序能取的先由程序取：正文的文字、链接、附件和日期的写法，都由程序先整理出来；模型只做程序做不了的判断，比如哪个日期是报名截止、这条通知属于哪个项目。LLM 读整理好的正文和附件，按固定的结构输出：

- **通知是什么**：报名通知、补充、延期、名单或结果，或者无关。
- **属于哪个项目**：学校、学院、年份、类型和项目名称。
- **字段**：每个字段附上原文里的那句话作为证据，再给一个置信度。

| 字段 | 说明 |
| --- | --- |
| 报名时间 | 开始和截止；材料截止和报名截止不同时，分开记 |
| 报名链接 | 报名系统的地址 |
| 活动时间 | 开始和结束，线上还是线下，地点 |
| 考核方式 | 笔试、机试、面试等 |
| 招收专业 | 专业或方向 |
| 报名要求 | 排名、外语成绩等 |
| 要交的材料 | 申请表、成绩单、推荐信等 |
| 名额 | 写了才有 |
| 待遇 | 路费、住宿等 |
| 联系方式 | 邮箱、电话 |
| 附件 | 申请表模板等，链接到快照里的文件 |

### 8.3 校验

- 证据必须能在快照的文字里原样找到。找不到的字段不上表，进审核页。
- 时间统一成北京时间。「24 时」算当天结束；只写了日期的截止时间按当天结束算，显示时只显示日期；没写年份的按发布时间推，跨年的（12 月发的通知写「1 月 10 日截止」）算下一年。
- 截止早于发布时间这类明显不对的，进审核页。
- 置信度低的字段，先进审核页，审核通过才上表。

### 8.4 归并与版本

归并在网站上做：要看已有的项目和人工改过的值，这些都在网站的数据库里。

- 按学校、学院、年份和类型找已有的项目：找到了，这条通知作为它的新版本；找不到，新建一个项目。
- 一个学院同一年同一类型有好几个项目（比如分方向的夏令营）时，再比抽取出的项目名称；还认不准是哪个的，进审核页由人判断。网站不调用模型。
- 新版本改了哪些字段，和上一版逐个字段对比，记下来。截止时间变了，订阅的人收到邮件（第 11 节）。
- 人工改过的字段不会被抓取覆盖。新版本的值和人工改的值不一样时，进审核页。

### 8.5 实验

- 从第一批来源抓真实的通知，做成标注集：初筛用标题和标注，抽取用正文和各字段的正确值。标注集只放网址、标题和标注，全文和快照不进仓库。
- 初筛看召回率（有没有漏），以及能挡掉多少无关的通知；拿关键词规则当基线比一比。
- 抽取看各字段的准确率，重点是截止时间。
- 改模型、提示词或门槛，都要在标注集上重跑一遍，结果贴在 PR 里。

### 8.6 成本

- 初筛挡掉大部分通知；每条通知只抽取一次，正文变了才再抽。
- 每次调用都记下用量，按天汇总显示在抓取看板上。
- 估算：旺季每天几十条通知进 LLM，用便宜的模型，一天花不了几块钱。

## 9. 内容

### 9.1 学校、学院和项目

- **学校**：名称、层次（C9、985、211、双一流等，可以有几个）和地区。
- **学院**：泛指招生单位，包括学院、研究所和研究生院，属于一个学校（研究所属于中科院等）。院校清单里的学院不一定已经接入来源，没接入的也能关注。
- **项目**：一个学院某一年的一次招生活动，比如「某大学计算机学院 2027 年夏令营」。字段见第 8.2 节，每个字段有值、证据和来源的版本。
- **类型**：冬令营、夏令营、预推免、九推。各校的叫法不同，按实际归类，比如电科的「优本计划」算预推免。
- **状态**：按时间算出未开始、报名中、已截止；另有「已核对」和「有争议」两个标记。

### 9.2 已核对

- L3 以上或管理员核对过一个项目的全部字段后，标记「已核对」，记下是谁、什么时候核对的。
- 之后有了新版本，或者有字段被修改，标记取消，等再次核对。

### 9.3 学院标签

- 公开的标签贴在学院上，不随某一年的通知走，往年的评价也算数。
- 只能从管理员预设的标签里选，比如「对双非友好」「卡本科出身」「看重科研」「看重竞赛」「有机试」。用词要中性，不用「歧视」这类字眼，免得引战。
- 每人每个标签一票，可以撤回。页面上只显示人数，不显示是谁，但记录里有。
- 总表可以按标签筛选。
- 乱贴的标签管理员可以删，删除也有记录。

### 9.4 我的报名

- 每人可以给任何项目记进度：想报、已报名、已交材料、入营、优营、放弃，另外可以写一段备注。
- 只有自己看得到，不占订阅名额。

## 10. 页面

- 风格和鼠洞一致；手机优先，兼容 QQ 内置浏览器。
- 筛选条件写在网址里：链接可以分享，用浏览器操作网页的 Agent 也好上手。

| 页面 | 内容 |
| --- | --- |
| 总表（首页） | 项目列表：学校和学院、类型、报名截止和倒计时、订阅人数、原文链接。按年份、层次、地区、方向、类型、状态和学院标签筛选；按截止时间、发布时间、订阅人数排序；按学校、学院、项目名和关键词搜索。访客只看到截止时间最近的 5 条 |
| 详情页 | 最上面是原文链接，下面是各字段和证据、版本记录和每一版的快照、修改记录，以及订阅、记报名、反馈和修改的按钮 |
| 学院页 | 这个学院历年的项目、学院标签、关注按钮和来源 |
| 我的 | 订阅、关注、报名记录（可以按进度筛选）、邮件开关、个人令牌 |
| 抓取看板 | 每天每个来源的结果（第 7.5 节） |
| 求收录 | 收录申请、进度和同求人数（第 10.1 节） |
| 审核页 | L3 以上：待审的修改申请、拿不准的字段和归并、有争议的项目，以及全站的「最近修改」 |
| 管理 | 管理员：来源（接入、配置、试抓）、院校清单、学院标签预设、用户的修改权限；站长：系统设置 |

### 10.1 求收录

- 选好学校、填上学院就能提，知道通知页面的链接也可以附上。
- 别人提过的点「同求」。关注了还没接入来源的学院，也算一次同求。
- 按同求人数排队，人多的先接。进度分为排队中、接入中、已收录、暂时抓不了（写明原因）。
- 收录后发邮件告诉提过和同求的人。

## 11. 提醒

邮件都发到 `QQ号@qq.com`，用 QQ 邮箱的 SMTP 发，可以配几个邮箱轮流用，和鼠洞一样。每类邮件都可以在「我的」里关掉。

| 提醒 | 什么时候发 |
| --- | --- |
| 订阅的项目快截止了 | 截止前 3 天的上午 9 点；订阅时离截止已经不到 3 天的，马上发一封 |
| 订阅的项目截止时间变了 | 新版本或者人工修改改了截止时间时 |
| 关注的学院有新通知 | 发现后就发，同一个人一小时内的合成一封；报名、补充、延期通知，以及入营、优营名单和考核结果都算 |
| 求收录的学院收录了 | 收录时 |

- 每人同时最多订阅 10 个项目，截止了的不占名额。关注的学院不限个数。
- 有争议的项目照常提醒，邮件里注明「有争议，请以原文为准」（第 12.3 节）。
- **群汇总**：每天上午 9 点，插件从鼠钟取一份汇总发到群里：昨天新增了几个项目，3 天内截止的有几个，附上链接。每天只发这一条，不 @ 人，免得触发 QQ 风控。

## 12. 纠错、审核与争议

### 12.1 反馈

每个项目旁有「反馈」按钮，有两种用法：

- 只说这条有问题：写明哪里不对；
- 给出改成什么：这就是修改申请，要写理由、附依据（原文链接或截图）。

L3 以上可以不提申请，直接修改，同样要写理由、附依据。两种反馈都算进争议的人数。

### 12.2 审核

- L3 以上在审核页处理修改申请：通过就按申请修改，驳回要写理由。申请人在「我的」里能看到结果。
- 抽取拿不准的字段、拿不准的归并、和人工改过的值冲突的新版本，也都在审核页处理。

### 12.3 争议

- 3 个不同的人反馈同一个项目有问题（修改申请也算），这个项目自动标上「有争议」，排到审核页最前面。
- 管理员复核：改正，或者确认没错，然后取消标记；之后的反馈重新计数。
- 有争议期间提醒照发：万一信息其实没错，停了提醒反而会让人错过截止。

### 12.4 记录和撤销

- 每次修改、审核、标记已核对和复核争议，都记下谁、什么时候、通过网页还是 Agent、改了哪个字段、改前改后的值、理由和依据。
- 登录后都能看记录：每个项目的详情页有它的修改记录，审核页有全站的「最近修改」。
- 任何一次修改都能一键撤销，撤销本身也记下。
- 管理员可以一次撤销某人的全部修改，并收回他的修改权限。
- 管理员的其他操作，比如接入和修改来源、删除项目、改权限、改标签预设、改系统设置，都记进操作日志。

## 13. Agent 接入

- **MCP**：提供 MCP 服务，支持 MCP 的 Agent（Claude Code、Codex、Cursor 等）加一行配置就能用。MCP 是接口的薄包装：工具由接口的定义生成，不单独写一套，见[接口 §4](api.md#4-mcp)。
- **API**：开放 API，附 OpenAPI 文档；登录后可以下载全部数据。网站根目录放 `/llms.txt`，说明网站和接口怎么用。
- **个人令牌**：在「我的」里生成，可以选权限范围：只读，或者再加上个人操作（订阅、关注、报名记录、反馈和修改申请）。令牌随时可以作废，库里只存 SHA-256。
- **不能做的**：直接修改、审核和管理只能本人在网页上做。
- **记录和限制**：通过令牌做的操作，记录里标明「通过 Agent」；每个令牌单独限制请求频率。

## 14. 性能与资源

目标见第 1 节，实测见第 5.2 节。

- 一年的项目一次发给浏览器，筛选、排序、搜索都在浏览器里做，不用每次问服务器；往年的按需再取。3000 个项目压缩后约 100–140KB，手机上解析加筛选不到 15 毫秒，所以要省的是带宽：首屏由服务端渲染，不等这份数据；只发给登录的人；数据变了才重新生成、预先压缩，没变时浏览器用缓存。
- 页面由服务端渲染，首屏不等脚本。
- 页面和接口只带用得上的字段。
- 抓取、初筛和抽取在抓取节点上跑，不占网站服务器的 CPU 和内存。抓取节点交来的快照和附件是网站服务器的入站流量，不占出口带宽。
- 网站服务器的出口带宽只有 25Mbps，和鼠洞等服务共用，页面大小按鼠洞的预算来。

## 15. 安全与隐私

- 会话和个人令牌是高熵的随机值，库里只存 SHA-256。
- QQ 号只用来发邮件，页面和接口都不显示。
- 订阅人数和学院标签只显示人数；报名记录只有本人能看。
- 交给 LLM 和判别模型的只有公开的通知内容，不带任何用户的数据。
- **最小权限**：抓取节点只有抓取节点令牌和模型的 key，拿不到用户的数据；网站没有模型的 key。抓取节点令牌只能调[抓取节点接口](api.md#6-抓取节点)，库里只存 SHA-256。
- **外部内容当作数据**：网页、附件和模型输出都不可信。快照显示前按白名单净化，不执行其中的脚本；通知里的文字只作为要读的材料交给模型，写在提示词里的指令和它分开，通知里写的「指令」不起作用。
- 抓取遵守第 7.3 节；不抓要登录才能看的内容，不破解验证码。
- 快照只给登录的人看，始终链接回原文。
- 页面上的站外链接（原文、报名系统）加 `rel="nofollow noopener"`。

## 16. 部署与运维

| 部分 | 放在哪 | 说明 |
| --- | --- | --- |
| 网站 | 香港的服务器，和鼠洞同一台 | 容器部署，前面是 1Panel 的 OpenResty；数据库用服务器上 1Panel 的 PostgreSQL |
| 抓取节点 | 上海的机器：4 核、3.6GB 内存 | 容器部署；浏览器抓取同时最多开 2 个页面，文字识别一次只做一张，内存峰值约 1.4GB（第 5.2 节） |

- 抓取节点每分钟向网站领一次活：到期要抓的来源、要重抓的通知和管理员要试抓的来源。抓取节点停了，网站照常能用，只是没有新数据；抓取看板会显示抓取节点多久没来领活。
- 为什么分开：实测 11 所学校和研究所的官网和研招网，香港和上海都能访问（浙大要用 HTTP），但从上海访问快 2–4 倍；浏览器抓取和附件解析吃 CPU 和内存，放在上海也不占网站服务器的资源。判别和抽取都调用外部接口，抓取节点不跑模型。
- **备份**：数据库和快照每天备份，做法参照鼠洞。
- **监控**：除了抓取看板，网站也接入服务器上的监控，和鼠洞一样。
