# 数据

人工整理的数据，都是 UTF-8 编码：来源清单和初筛标注集是 CSV，抽取标注集要写出项目和字段的层次，是 JSON。提交前按各份写的顺序排好：新的条目插在该在的位置，不都加在文件末尾，几个人同时补充时改的是不同的地方，合并时不容易冲突。

- CSV 用逗号分隔，第一行是列名。用文本编辑器改，或者在 Excel 里另存为「CSV UTF-8」。Excel 默认存的 CSV 是 GBK 编码，提交上来是乱码。
- CSV 某一格里有英文逗号或双引号的，整格用双引号括起来，里面的双引号写两遍。备注里用中文逗号就不用括。
- 只收公开的页面。只放网址、标题和标注，不放通知的正文、快照和附件。
- 用脚本收集的，请求都经过 `crawler` 的 `Fetcher`（[开发约定 §2](../docs/development.md#2-抓取和判别)），它会守抓取的规矩。

## 来源清单 `sources.csv`

第一批要接入的通知列表页，一行一个列表页。一个学院有几个列表页（学院的、研究生院的），就写几行。

| 列 | 内容 |
| --- | --- |
| `school` | 学校的全称，比如「电子科技大学」 |
| `college` | 学院的全称，以官网为准；研究生院就写「研究生院」 |
| `url` | 通知列表页的网址，打开确认过 |
| `months` | 往年发保研通知的大概月份，用空格隔开，比如 `5 6 9` |
| `note` | 打开时遇到的情况，比如「要执行脚本才显示内容」「只能用 HTTP」；没有就空着 |

同一所学校的行写在一起，学校之间按拼音排，大致对就行；同一所学校里按 `college`、`url` 排。

## 初筛标注集 `screening.csv`

初筛实验用的通知标题和标注（[总体设计 §8.5](../docs/design.md#85-实验)），一行一条通知，明显无关的通知也要收。

| 列 | 内容 |
| --- | --- |
| `source_url` | 通知所在列表页的网址 |
| `section` | 列表页的栏目名，比如「通知公告」 |
| `url` | 通知的网址 |
| `title` | 列表上显示的标题，原样复制 |
| `relevant` | 是保研招生相关的通知填 `1`，不是填 `0`；范围见[总体设计 §8.1](../docs/design.md#81-初筛) |
| `note` | 拿不准的写明原因；没有就空着 |

按 `source_url`、`url` 的字母顺序排，同一条通知只写一行。

## 抽取标注集 `extraction.json`

抽取实验用的正确答案（[总体设计 §8.5](../docs/design.md#85-实验)），一条通知一项，写它涉及的项目和字段的正确值。正文不进仓库，评估时按网址重新抓。

```json
[
  {
    "url": "https://cs.example.edu.cn/info/1001.htm",
    "title": "计算机学院关于举办2026年全国优秀大学生夏令营的通知",
    "published_at": "2026-05-19",
    "school": "某某大学",
    "programs": [
      {
        "college": "计算机学院",
        "cohort": 2027,
        "kind": "summer_camp",
        "role": "call",
        "fields": {
          "apply": {
            "start": { "date": "2026-05-20" },
            "end": { "date": "2026-06-14", "time": "17:00" }
          },
          "apply_url": "https://yz.example.edu.cn/camp",
          "event": {
            "start": { "date": "2026-07-06" },
            "end": { "date": "2026-07-09" },
            "mode": "offline"
          },
          "degrees": ["master", "direct_phd"]
        }
      }
    ]
  }
]
```

| 键 | 内容 |
| --- | --- |
| `url` | 通知的网址 |
| `title` | 列表上显示的标题，原样复制 |
| `published_at` | 列表上的发布日期，推算没写年份的日期要用 |
| `school`、`college` | 学校和学院的全称，和 `sources.csv` 一致；学院按[总体设计 §8.2](../docs/design.md#82-抽取)的规则归 |
| `programs` | 通知涉及的项目；无关的通知写 `[]`，这样的也要收一些 |

- `cohort`、`kind`、`role` 和字段的含义、值的格式，都照[总体设计 §8.2](../docs/design.md#82-抽取)。
- 字段只标能逐项比对的 `apply`、`apply_url`、`event`、`degrees`。其他字段是一条条的文字，评估时人工抽查，不用标。
- 通知里没写的字段不写，写着「另行通知」的也不写。
- 不写证据：原文的句子不进仓库，证据由评估脚本在重新抓到的原文里检查。
- 按 `url` 的字母顺序排，同一条通知只写一项；缩进两个空格。
